# 音频处理说明

## 处理流程

```text
本地文件 → 浏览器解码为 48 kHz 浮点 PCM → Worker
        → Rubber Band R3 分析与转调 → 浮点试听 / 24-bit WAV
```

播放器播放已经处理好的完整音频。修改音高不会即时改变已生成的音频，需要重新点击生成。

## 只变调，保持原速

升降 `s` 个半音对应音高比例 `2 ** (s / 12)`。引擎时间比例固定为 1，并使用离线的 study / process 两阶段处理。

处理输出保留与解码输入相同的采样点数，极短片段补足分析尾部后裁回原长度。这里的“时长保持”指与浏览器解码后的输入相同；解码器对容器填充或延迟的处理可能与其他软件不同。

原调（0 半音）直接复制解码 PCM，不运行转调。输入若并非 48 kHz，解码阶段仍会重采样。

## 共振峰保留

构造引擎时设置：

| 设置 | 用途 |
|---|---|
| EngineFiner | 使用 Rubber Band R3 |
| FormantPreserved | 尽量保留输入频谱包络 |
| ChannelsTogether | 对立体声保持较紧密的声道同步 |
| ThreadingNever | 在一个 Worker 内运行 |
| timeRatio = 1 | 保持原始速度 |

程序检查实际引擎版本为 R3。共振峰是影响人声和乐器声音特征的共振结构；补偿它可以减少转调带来的音色变化，但不能保证原声音色完全不变。复杂混音、打击乐瞬态、较大升降幅度仍可能有伪影。

若非零转调后峰值超过 0.999，程序只施加统一衰减以避免导出削波，不执行动态压缩。文件间的平均电平差不能全部归因于位深，也不等于听觉响度 LUFS。

## 为什么 WAV 变大

PCM 数据大小 = 时长 × 采样率 × 声道数 × 位深 / 8。

48 kHz 立体声每秒的大小为：

- 16-bit：192,000 字节。
- 24-bit：288,000 字节。

因此相同时长下 24-bit 的数据体积是 16-bit 的 1.5 倍。更高存储精度不表示音频内容更多，也不表示转调更准确。24-bit 是当前导出设置，与是否保留共振峰是两个独立问题。

## 验证范围

音频测试使用生成的正弦波和合成元音，不包含用户音乐。测试覆盖音高比、时长、左右声道、短片段、0 半音、共振峰补偿与 WAV 格式。共振峰测试验证合成信号的包络峰值向原位置保持的趋势，不能推广为对所有歌曲的听感保证。

频谱、波形、RMS 和文件大小可以帮助排查问题；若比较音色优劣，应使用同一源音频、相同设置、音量匹配和听觉比较。
