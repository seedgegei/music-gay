# 导出文件说明：为什么转调后的音频会变大？

本工具当前统一导出 **48 kHz、24-bit 整数 PCM WAV**。源文件的格式可能不同，因此即使只降一个半音，导出文件也可能明显变大。

最常见的原因是：**压缩音频被展开为未压缩 PCM，或者位深从 16-bit 变成了 24-bit。** 文件大小主要取决于保存格式，并不能直接代表听感、音色保留效果或转调质量。

## 1. 程序实际保存了什么

| 项目 | 当前行为 |
|---|---|
| 文件格式 | WAV 容器，未压缩整数 PCM 编码 |
| 采样率 | 48,000 Hz，每个声道每秒 48,000 个采样点 |
| 位深 | 24-bit，每个声道的每个采样点占 3 字节 |
| 声道 | 保留解码后的单声道或立体声 |
| 时长 | 保留解码后的采样帧数，转调时间比例固定为 1 |
| 转调幅度 | −12 到 +12 半音，不改变以上保存规格 |

音乐先由浏览器解码、转换到 48 kHz，再完成转调并写入 WAV。即使选择 **0 半音**，导出仍会使用这些规格，不会直接复制原文件。

“WAV”是容器名称；比较其他软件的 WAV 时，还要检查内部编码和位深。本说明中的大小计算针对未压缩 PCM。

## 2. 文件大小如何计算

对本程序使用的 16-bit / 24-bit 这类整字节 PCM，可按下面的公式估算音频数据大小：

```text
数据大小（字节）= 时长（秒）× 采样率（Hz）× 声道数 × 位深（bit）÷ 8
```

这里的每秒字节数等于采样率乘以每帧字节数，字段定义可参考 [Microsoft 的 WAVEFORMATEX 说明](https://learn.microsoft.com/en-us/previous-versions/dd757713%28v%3Dvs.85%29)。

本工具实际导出的精确大小为：

```text
PCM 数据字节数 = 采样帧数 × 声道数 × 3
WAV 文件字节数 = 44 + PCM 数据字节数 + 对齐字节
```

其中 44 字节是本工具写入的文件头；数据长度为奇数时，再补 1 字节对齐。其他软件可能写入额外的封面或元数据，文件头不一定只有 44 字节。

### 相同音乐：16-bit 与 24-bit

以下均为 **48 kHz、立体声**，忽略几十字节的文件头，按 `1 MB = 1,000,000 字节` 计算：

| 时长 | 16-bit PCM | 本工具的 24-bit PCM | 增加体积 |
|---|---:|---:|---:|
| 1 分钟 | 11.520 MB | 17.280 MB | 5.760 MB |
| 3 分 8 秒 | 36.096 MB | 54.144 MB | 18.048 MB |
| 5 分钟 | 57.600 MB | 86.400 MB | 28.800 MB |
| 10 分钟 | 115.200 MB | 172.800 MB | 57.600 MB |

每个采样点从 2 字节变为 3 字节，所以 `24 ÷ 16 = 1.5`：**体积增加 50%**。

例如，一个约 36 MB 的 16-bit 文件导出后约为 54 MB，实际增加约 **18 MB**。54 MB 是导出文件的总大小，不能理解成“额外增加了 54 MB”。

有些系统按二进制单位显示大小：`1 MiB = 1,048,576 字节`。同一个 54.144 MB 文件约为 51.64 MiB，字节数并没有变化。

## 3. 哪些因素会让体积增加

### 压缩格式转换为未压缩 PCM

MP3、AAC 等通常使用有损压缩；FLAC 使用无损压缩。本程序解码它们后，导出的是未压缩 PCM，不能再按原来的压缩码率估算大小。

例如，188 秒、320 kbps 的 MP3，按码率估算约为 **7.52 MB**；相同时长的 48 kHz、立体声、24-bit PCM 约为 **54.144 MB**。这只是保存方式的差异。转成 WAV 无法恢复源 MP3 压缩时已经丢失的信息。

### 位深、采样率或声道数不同

比较时一次只改变一个条件：

| 条件变化 | 对未压缩 PCM 数据大小的影响 |
|---|---|
| 16-bit → 24-bit | 增加 50% |
| 44.1 kHz → 48 kHz | 增加约 8.84% |
| 单声道 → 立体声 | 增加 100% |
| 时长增加 1% | 增加 1% |

多个变化需要相乘。例如，44.1 kHz、16-bit 转为 48 kHz、24-bit，在时长和声道数相同的条件下，数据大小约为原来的 `48,000 ÷ 44,100 × 24 ÷ 16 ≈ 1.633` 倍，即增加约 **63.27%**。

声道数是比较其他软件时需要检查的因素；本工具保留输入解码后的声道数，不会为了转调把单声道变成立体声。

导出也不一定更大。例如，同采样率、同声道、同时长的 32-bit PCM 转为 24-bit PCM，数据大小会减少 25%。

### 时长、静音和额外信息

未压缩 PCM 中，静音与音乐每秒占用的字节数相同。其他软件如果保留了更多头尾静音，文件也会稍大；封面和元数据同样占空间。

本程序保留与浏览器解码结果相同的采样帧数。不同解码器对压缩音频的延迟、填充处理可能不同；若与其他软件输出有少量时长差，应检查实际帧数，不能仅凭文件名判断原因。

## 4. 为什么文件大了，人耳听起来却差不多

位深决定振幅数值的存储精度。24-bit 用更多字节表示每个采样点，但音乐的旋律、节奏和主要声音内容不会因此变多。增加位深也不能补回源文件中已经丢失的细节。

实际能否听出差异，与录音噪声、播放环境、音量、设备和后续处理有关。**体积大 50%，不代表听感改善 50%。** 同样，也不能凭“听起来差不多”断言两份数据完全相同。

比较转调效果时，应使用同一首源音频、相同半音数，并尽量匹配试听音量，重点听人声质感、齿音、打击乐瞬态和尾音。

## 5. 保留音色为什么不要求更大的文件

共振峰保留影响转调算法如何处理声音，位深影响处理结果如何存储。这是两个独立的设置。

在 **时长、采样率、声道数、位深完全相同** 的未压缩 PCM 中，升调、降调、音量变化或启用共振峰补偿，都不会因为波形变复杂而增加数据字节数。

当前采用 24-bit 是程序的导出精度选择。将同一处理结果转换为 16-bit，并不会关闭或撤销已经完成的共振峰补偿；转换会引入相应的量化误差。

## 6. 需要更小文件时怎么办

当前界面只提供 24-bit WAV，尚不能选择 16-bit、FLAC、MP3 或 AAC。下载后可使用支持相应格式的音频软件另存：

| 保存方式 | 体积与声音的取舍 |
|---|---|
| 16-bit WAV | 相同其他参数下，比 24-bit PCM 数据小约三分之一；降低位深涉及量化，转换时可使用合适的抖动选项，见 [Audacity 的抖动说明](https://manual.audacityteam.org/man/dither.html) |
| FLAC | 对已导出的 PCM 做无损压缩，可保留其采样数值；压缩率取决于内容，没有固定缩小比例，见 [FLAC 官方 FAQ](https://xiph.org/flac/faq.html) |
| MP3 / AAC | 按目标码率压缩，通常适合需要较小文件的分享场景；会产生新的有损编码误差 |

“16-bit 升到 24-bit 增加 50%”与“24-bit 降到 16-bit 减少约 33.3%”都成立，因为计算百分比的基数不同。

## 7. 比较两份文件时检查什么

在音频软件的文件属性中，依次查看 **实际编码、位深、采样率、声道数、时长和字节数**。先用公式计算 PCM 数据量，再检查文件头、额外静音或元数据。

只看 `.wav` 扩展名、文件名里的“降一个半音”或播放时的音量，无法解释体积差。对格式参数相同的 PCM，波形更复杂、声音更响或转调幅度更大，都不会让每个采样点多占字节。
